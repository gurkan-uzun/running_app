## Work Package 3: Backend Implementation & Data Engineering

We have successfully initialized the C++ backend and implemented core components for the routing engine.

### 1. C++ Native Environment Setup
- **Status**: Completed
- **Details**:
    - Created the `native` directory structure for C++ source code.
    - Configured `CMakeLists.txt` to build the `running_app_backend` shared library.
    - Configured `android/app/build.gradle.kts` to compile and link the native code during the Android build process.
    - Added `ffi` dependency to `pubspec.yaml` to prepare for Dart-to-C++ communication.

### 2. OpenStreetMap (OSM) Data Pipeline (T3.1)
- **Status**: Completed (Initial Implementation)
- **Details**:
    - **Graph Data Structures**: Defined `Node` (lat/lon), `Edge` (weight), and `Graph` (adjacency list) structures.
    - **XML Parsing**: Integrated `TinyXML2` library directly into the project sources.
    - **OSM Parser**: Implemented `OsmParser` class to read `.osm` XML files.
        - Parses `<node>` elements into Graph Nodes.
        - Parses `<way>` elements into Graph Edges.
        - Calculates edge weights using the **Haversine formula** (distance in meters).

### 3. Pathfinding Algorithm (T3.3)
- **Status**: Completed (Baseline)
- **Details**:
    - Implemented **Dijkstra's Algorithm** using a priority queue.
    - Capable of finding the shortest path between two nodes in the constructed Graph.
    - Verified via compilation and basic integration tests.

### 4. POI Service Architecture (O3.2)
- **Status**: Completed (Architecture & Mock)
- **Details**:
    - Designed a flexible **Strategy Pattern** for POI data fetching.
    - **IPoiProvider**: Abstract interface to decouple the app from specific data sources (Google Maps vs OSM).
    - **PoiService**: Service class to manage providers and fetch POIs.
    - **MockPoiProvider**: Concrete implementation returning fake data, used to verify the architecture without needing an API key immediately.
